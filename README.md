# Journal

A personal journaling app built with React and Vite, with an Express API and PostgreSQL for storage.

## Features

- **Entries** with a date, title, mood (Awful, Low, Okay, Good, Great), and tags. Entries save automatically as you type.
- **Search and tag filters** in the sidebar. Search looks at titles, entry text, and tags.
- **Created and edited times** shown in the entry list and the editor.
- **Writing prompts** from a built-in list, or generated by Claude (optional; needs an Anthropic API key).
- **Rich-text editor** with a toolbar and keyboard shortcuts: bold, italic, underline, strikethrough, inline code, headings, bulleted and numbered lists, quotes, code blocks, dividers, links, text alignment, and book-style first-line indents.
- **Images** added from the toolbar or by dragging files into an entry, with optional alt text. Images can be resized (Small, Medium, Full width, or by dragging) and positioned on their own line, centered, or with text wrapping around them.

## Requirements

- Node.js 20.6 or newer
- PostgreSQL
- An Anthropic API key, only if you want Claude-generated prompts

## Setup

```bash
npm install
cp .env.example .env    # then fill in the values below
createdb journal        # or create the database however you prefer
```

Settings in `.env`:

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | PostgreSQL connection string, e.g. `postgres://user:password@localhost:5432/journal` |
| `PORT` | Port for the API server (default `3001`) |
| `ANTHROPIC_API_KEY` | Optional. Enables "Ask Claude for one" in the prompt bar |

`.env` is listed in `.gitignore`, so your key and database password stay out of git.

## Running

Run the API and the frontend in two terminals, both from the repo root:

```bash
npm run server   # Express API on http://localhost:3001
npm run dev      # Vite frontend, usually http://localhost:5173
```

The server creates its tables on startup if they don't exist (see `server/schema.sql`), so there's no separate migration step.

Use Ctrl instead of ⌘ on Windows and Linux. Hovering a toolbar button also shows its shortcut.

| --- | --- |

| Strikethrough | ⌘⇧S |

| Heading / subheading | ⌘⌥2 / ⌘⌥3 |
| Bulleted / numbered list | ⌘⇧8 / ⌘⇧7 |
| Quote | ⌘⇧B |
| Code block | ⌘⌥C |
| Link | ⌘K |
| Align left / center / right / justify | ⌘⇧L / ⌘⇧E / ⌘⇧R / ⌘⇧J |

Markdown-style typing also works: `## ` starts a heading, `- ` a bulleted list, `> ` a quote, ```` ``` ```` a code block, and `---` a divider.

## Images

- JPEG, PNG, GIF, and WebP, up to 10 MB. The server checks each file's actual contents, not just its name.
- Photos larger than 2000 pixels on their longest side are scaled down in the browser before uploading. GIFs are left unchanged so they keep their animation.
- To resize or reposition an image, click it (or select it with the arrow keys) to show its menu and drag handle. Sizes are saved as a share of the writing width, so they adapt to the screen.
- Wrapped images go back to their own line when the writing area is narrower than 480 pixels, for example on phones.
- Images are stored in PostgreSQL. They're deleted only when the entry they belong to is deleted, and not if another entry also uses them. Images removed from an entry while editing are kept.

## How data is stored

- Entry text is saved as the editor's JSON document, stored as text in the `body` column. Entries written before the formatting editor was added are plain text; they're converted when opened and saved in the new format on their first edit.
- Edits are sent to the server half a second after you stop typing. Closing the tab within that half second can lose the last few keystrokes.

## Development notes

- The Vite dev server forwards `/api/entries` and `/api/images` to the Express server, and `/api/anthropic` to the Anthropic API with your key added. These proxies only exist in `npm run dev`. To deploy the app, you'll need your own setup to serve the built frontend (`npm run build`) and route those requests, including a server-side endpoint for Claude prompts so the API key never reaches the browser.
- The Claude model used for prompts is set at the top of the API section in `src/prompts.js`.

## PDF export (separate branch)

PDF export lives on its own branch and isn't part of main. It adds an Export PDF button to the editor and a way to select several entries in the sidebar and export them as one PDF (one entry per page, oldest first, with the date and mood under each title). It uses Puppeteer, which renders the PDF with a headless copy of Chrome.

The examples below call the branch `pdf-export`; use your branch's actual name.

**Keeping it up to date.** Merge main into the export branch from time to time (or merge each feature branch into both), so it doesn't fall behind:

```bash
git checkout pdf-export
git merge main
```

**Bringing it into main.** First check which commits the branch has that main doesn't:

```bash
git log --oneline main..pdf-export
```

- If that lists the export commit, merge it: `git checkout main && git merge pdf-export`.
- If it lists nothing, the export was committed on main before being removed, so a merge won't bring it back. Find the removal commit with `git log --oneline` and reverse it with `git revert <commit-id>`.

**Setting it up after bringing it back:**

1. Run `npm install` to get Puppeteer.
2. Puppeteer needs its own copy of Chrome. It usually downloads during `npm install`; if not, run `npx puppeteer browsers install chrome`.
3. If that download fails or times out, point Puppeteer at your installed Google Chrome instead by adding this to `.env`:

   ```bash
   PUPPETEER_EXECUTABLE_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
   ```

4. Restart `npm run server` and `npm run dev`.

PDFs are A4 by default; change `format: 'A4'` to `format: 'Letter'` in `server/exportPdf.js` for US Letter.
